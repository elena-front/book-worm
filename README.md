

Для реализации описанного функционала можно определить следующие контракты REST API:

1. Получение списка книг:
* HTTP-метод: GET.
* Endpoint: /api/books.
* Параметры запроса:
  * page (опционально) — номер страницы для пагинации;
  * limit (опционально) — количество книг на странице;
  * sort (опционально) — параметр для сортировки (например, по рейтингу, названию и т. д.).
* Ответ сервера (200 OK): массив объектов, каждый из которых содержит информацию о книге (ID, название, автор, рейтинг, URL обложки и т. д.).

2. Добавление новой книги:
* HTTP-метод: POST.
* Endpoint: /api/books.
* Тело запроса (JSON):
  

  {
    "title": "Название книги",
    "author": "Автор",
    "cover": "URL или идентификатор файла с обложкой"
  }
  
* Ответ сервера (201 Created): объект с информацией о созданной книге и её ID.

3. Добавление книги в избранное:
* HTTP-метод: POST.
* Endpoint: /api/users/{userId}/favorites.
* Параметры пути:
  * {userId} — ID пользователя.
* Тело запроса (JSON):
  

  {
    "bookId": "ID книги"
  }
  
* Ответ сервера (201 Created): сообщение об успешном добавлении книги в избранное или объект с информацией о книге в избранном.

4. Получение списка избранных книг пользователя:
* HTTP-метод: GET.
* Endpoint: /api/users/{userId}/favorites.
* Параметры пути:
  * {userId} — ID пользователя.
* Ответ сервера (200 OK): массив объектов с информацией о книгах, находящихся в избранном у пользователя.

5. Голосование за книгу:
* HTTP-метод: PUT.
* Endpoint: /api/books/{bookId}/rating.
* Параметры пути:
  * {bookId} — ID книги.
* Тело запроса (JSON):
  

  {
    "rating": 5  // оценка от 1 до 5
  }
  
* Ответ сервера (200 OK или 204 No Content): сообщение об успешном голосовании или пустой ответ.

6. Добавление комментария к книге:
* HTTP-метод: POST.
* Endpoint: /api/books/{bookId}/comments.
* Параметры пути:
  * {bookId} — ID книги.
* Тело запроса (JSON):
  

  {
    "text": "Текст комментария",
    "userId": "ID пользователя"
  }
  
* Ответ сервера (201 Created): объект с информацией о созданном комментарии.

7. Получение комментариев к книге:
* HTTP-method: GET.
* Endpoint: /api/books/{bookId}/comments.
* Параметры пути:
  * {bookId} — ID книги.
* Ответ сервера (200 OK): массив объектов с комментариями к книге.

Общие требования:
* Для авторизованных действий (добавление в избранное, голосование, добавление комментариев) требуется передавать токен авторизации в заголовке запроса, например, в поле Authorization.
* В случае ошибок сервер должен возвращать соответствующие HTTP-коды состояния (например, 401 Unauthorized, 403 Forbidden, 404 Not Found и т. д.) и информативные сообщения об ошибках в теле ответа.
